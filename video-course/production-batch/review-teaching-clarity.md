# Course clarity review — introduction through Lab 17

## Scope and method

Reviewed the current exports against their narration, word timings, shot manifests and original recording log. Every scene was inspected at its opening, middle and end; control changes and proposed replacement intervals receive denser source-frame inspection. This is an editorial review of real recorded frames and timed narration, not a claim of uninterrupted real-time listening to every export. The baseline is the privacy/pacing revision at `ca865db`. Times below refer to that baseline; the final change map will give revised positions.

The main obstacle is not missing architecture content. It is missing visual orientation between explanation and action. A learner hears “prepare”, “uncheck”, “attach” or “inspect” while looking at the next screen, an already changed state, or text too small to read. Extra seconds should buy understanding, not silent waiting.

## Editing decisions

- Preserve the accepted introduction, real Mac/Windows footage, technical outcomes, failure cases and course branding.
- Show the Director operation before its consequence: locate the control, explain the choice, show the click/confirmation, then return to Command Center. Do not manufacture a click or change UI values in postproduction.
- Use original motion handles where available. Freeze only to explain a visible state and label the hold. Do not stretch a mouse movement to match a long sentence.
- Use readable close-ups and timed emphasis around the actual control or evidence. Establish the full window before moving in. Avoid covering the field being discussed.
- Teach relevant framework mechanisms from Microsoft Learn, then connect them to the repository implementation and recorded behavior. Documentation is reference material, not evidence that this project implements every option described there.
- Keep the three human-control owners distinct: MCP input request, workflow approval node, and protected function invocation. Session memory and durable execution history remain separate concepts.
- Keep recorded limitations explicit: hosted retrieval was unavailable; optional Routines/Insights lessons demonstrate preparation, not successful cloud execution.
- Regenerate narration/captions/chapters together after timing changes. Recheck privacy before crops; a zoom must not reveal previously incidental account information.

## Implementation and verification

Implemented across the introduction and all 17 labs. The same local MP4 paths now contain the revised cuts. [Revised viewing ranges](review-teaching-ranges.md) identify every added or changed scene; [the review index](../review-index.md) links the videos, captions and labs.

The edits add narrated Director preparation, explicit before/after selections, confirmation close-ups, code/result crops, and timed emphasis. Sessions, retrieval, skills, workflow approval and protected-tool approval include captured Microsoft Learn references followed by repository code. Existing lecture slides, branded exercise cards, real Mac/Windows recordings, debugger exchanges, denial/stale-state cases and independent Hub verification remain. Holds are labeled “Paused for explanation”; recorded mouse movement is not synthesized or slowed. The case-memory orientation follows the grounded explanation before moving to the new asset.

The rendered review caught and corrected additional problems: checkbox clips ending before the selection changed, a case-recording clip continuing into the next request, a habitat crop continuing after return to Command Center, emphasis remaining after a page changed, and bottom crops concealing preparation/restart controls. The durable lesson now enlarges the actual revision/expiry review before interruption and preserves the same review after continuation.

Verification combines opening/middle/end frames for every baseline scene, timed narration inspection, denser source samples around control changes, and revised-export samples for edited scenes. It is not an uninterrupted real-time watch/listen of every final movie. Automated media checks decode every export, validate 1080p video/audio/subtitle streams, chapters and caption bounds, and check narration tails and long silence. See [machine-readable results](media-validation.json). This checks technical integrity and sampled teaching alignment; it is not a guarantee that no further editorial improvement remains.

Privacy masks remain upstream of crop/zoom/holds. Additional Mac shell identifiers are masked. Status-bar masks are relaxed only during explicitly reviewed fullscreen browser intervals so genuine confirmation buttons remain visible; editor identity masks are retained. No new cloud execution, app control, deployment or shared setting is implied by these edits. The existing hosted-retrieval and optional Routines/Insights limitations remain documented in the review index.

Repository checks: restore and format passed; 473 tests passed, four opt-in IDE integration tests skipped. The normal build could not replace the AppHost executable held by the running demo. An isolated `dotnet build --artifacts-path video-course/.build/code-validation` passed with zero errors and one Functions extension restore-during-build warning (AZFW0108). Python compilation and `git diff --check` also passed. No application source was changed in this editorial revision.

## Rebuilding the editorial revision

`prepare-clarity-edits.py` is the canonical set of editing decisions. It generates each unit's `teaching-edits.json`, which overlays its original shooting script and `shots.json` without renumbering original scene IDs. The introduction uses the same overlays over `lesson.py` and its motion shots. Edit the generator first, regenerate the manifests, then run the relevant renderer with `--phase all` so narration, captions, chapters and timed scripts agree.

The three renderers are `build_agentic_csharp.py` (00), `build_lab01.py` (01), and `build_course_lab.py` (02–17, selected with `COURSE_UNIT`). Source recordings, Learn captures, speech and outputs remain local/ignored and are required to reproduce the exports. A fresh Git clone contains the editorial instructions, not those media assets. Run `production-batch/validate_media.py` after the final render, then refresh the review-index durations and video hashes.
